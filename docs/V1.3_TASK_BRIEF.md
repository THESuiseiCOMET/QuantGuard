## 执行顺序与验收

### A：完整清理 Tushare（本次先完成）

- 删除 TushareHttpClient、TushareMarketDataProvider、TushareResponse。
- 删除 Tushare Token、URL、Provider 分支及旧 Token 配置接口、前后端类型、设置页面和错误提示。
- 删除专属测试，保留通用 MarketDataProvider 抽象与 PythonMarketDataProvider。
- 修复 MarketDataAutoSyncScheduler 依赖 TUSHARE_TOKEN 的错误；自动同步必须默认关闭。
- 更新当前 README，保留已发布版本文档的历史真实性。

### B：日线获取可靠性

- 实查 BaoStock 网络连接和历史请求，核对固定依赖版本是否需要有针对性升级，禁止盲目升级全部依赖。
- 检查超时、异常、空数据，普通 A 股失败后的 AKShare 备用逻辑。
- 处理 AKShare ETF 可能缺少 amount 的返回；核对股票代码、日期、涨跌幅、成交量和成交额。
- 检查 Java → Python → 上游的超时链，首次从 1990 年开始同步的成本，失败时错误消息及日志持久化。
- 分别验证普通 A 股、ETF、指数；严格区分离线模拟测试与真实网络测试，离线通过不能证明上游可用。

### C：日志和磁盘增长

- 检查 backend.out.log、backend.err.log、market-data.out.log、market-data.err.log、desktop-runtime.log、Spring Boot 和 Python 日志。
- 检查 Tauri append(true) 的持续追加，设计轮转、总大小上限和清理策略。
- 区分 H2 正常增长与日志、重复复制、缓存和临时文件残留；不得随意删除数据库或用户数据。

### D：桌面数据目录

- 逐步完善自定义数据目录、打开数据文件夹、安全备份和迁移、数据库与日志分离。
- 可考虑安装位置附近独立的 QuantGuard-Data，但不得默认写入受 Windows 权限或卸载管理的程序目录。
- 继续使用 H2 File，不以 CSV 替换数据库，必须保留和迁移旧用户数据。
- 现有实现已有 QUANTGUARD_DATA_DIR 环境变量和开发脚本参数，后续应先复用再补足用户入口。

### E：完整测试与构建

- 每阶段执行对应 Java、Python、Vue 检查，不为通过而删除、跳过失败测试。
- Windows 安装包继续使用 scripts/build-windows-release.ps1 等既有流程，不下载既有安装包或另造流程。
