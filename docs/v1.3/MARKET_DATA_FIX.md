# V1.3 B：行情修复

日期：2026-10-26。分支：refactor/v1.3-stability。主线问题是搜索超时和日线边界，不增加交易功能。

## 根因与修复

- 真实探针显示普通股票/ETF/指数日线可用，但 AKShare 全量股票目录 25 秒内未完成；BaoStock 全量目录也可能长时间阻塞。已移除 BaoStock 全量目录加载，改用实测可用的服务端代码/名称筛选。完整 6 位代码可区分沪深同码证券，名称搜索补充指数；输入不完整数字时不发起下载。
- AKShare 股票/ETF目录仅在需要的备用路径加载，指数目录按需缓存；主源元数据不被备用源覆盖，保留上市日和状态。最近查询元数据最多512条，补充源目录缓存6小时。
- BaoStock 预探测超时无法约束 SDK 后续请求；AKShare 部分函数不接受 timeout。外部 SDK 调用现在有硬截止时间：BaoStock 8秒，AKShare 12秒，最多同时2个短期工作进程；超时终止并join，避免超时后留下不断增加的线程/请求。已添加工作进程结果、异常、超时回收测试。打包入口提前 freeze_support。
- 股票主源超时、不可用、空表或格式异常时走 AKShare；所有返回按请求日期过滤，ETF缺少/空 amount 不再让整条日线失败，有值则保留。现有非空存储规则下，未知成交额沿用0哨兵，不估算；昨收缺失继续保留null。
- Python错误码/错误原因不再被通用500掩盖，记录来源失败；Java默认读超时60秒，前端目录65秒，使单源硬截止先发生。
- 首次隐式同步/导入改为近1年（可配1–30年），不再默认从1990回填；显式开始日期和全量刷新保留。自动同步仍默认关闭。
- BaoStock 0.9.4的官方包已对比：主要是API-key/VIP变更，没有修复上述超时，因此保留0.9.3，其他行情依赖也未升级。

## 边界
